# Task Service

Сервис для управления задачами с HTTP API на Go.

## Периодичность задач (тестовое задание)

Поддерживается создание **шаблона** повторяющейся задачи с правилом периодичности. Для подходящих календарных дат в выбранном горизонте создаются отдельные строки задач (**экземпляры**) с тем же заголовком и описанием, полями `series_template_id` (id шаблона) и `occurrence_date` (дата в UTC).

Типы правил (`recurrence.type`):

- `daily_interval` — каждый `interval_days`-й день от `start_date` (включительно).
- `monthly_day` — заданное число месяца `day_of_month` (1–30); в месяцах без такого числа день пропускается.
- `fixed_dates` — только даты из `specific_dates` (формат `YYYY-MM-DD`).
- `month_day_parity` — все дни месяца с чётным или нечётным **числом** (`month_day_parity`: `even` / `odd`).

При создании с `recurrence` поле `materialize_days` задаёт, на сколько календарных дней вперёд от `start_date` сгенерировать экземпляры (по умолчанию 90, максимум 366). Дальнейшее расширение — `POST /api/v1/tasks/{id}/materialize` с телом `{"until":"YYYY-MM-DD"}` ( `id` — **шаблон**, не экземпляр).

Удаление шаблона каскадно удаляет правило и все экземпляры.

### Допущения и ограничения

- Все даты трактуются в **UTC** (календарный день по UTC).
- Чётность/нечётность — по **дню месяца** (1–31), как в формулировке задания.
- Отдельного часового пояса пользователя нет; при необходимости его можно добавить поверх той же модели.
- Расписание после создания **не редактируется** через API (только удаление серии и создание заново); это сознательно упрощает модель данных.
- Экземпляры при создании получают копию `title`/`description`/`status` шаблона; смена текста у шаблона **не** обновляет уже созданные экземпляры.

## Требования

- Go `1.23+`
- Docker и Docker Compose

## Быстрый запуск через Docker Compose

```bash
docker compose up --build
```

После запуска сервис будет доступен по адресу `http://localhost:8080`.

Если `postgres` уже запускался ранее со старой схемой, пересоздай volume:

```bash
docker compose down -v
docker compose up --build
```

Причина в том, что SQL-файлы из `migrations/` монтируются в `docker-entrypoint-initdb.d` и применяются только при инициализации пустого data volume.

## Swagger

Swagger UI:

```text

```

OpenAPI JSON:

```text
http://localhost:8080/swagger/openapi.json
```

## API

Базовый префикс API:

```text
/api/v1
```

Основные маршруты:

- `POST /api/v1/tasks`
- `GET /api/v1/tasks`
- `POST /api/v1/tasks/{id}/materialize`
- `GET /api/v1/tasks/{id}`
- `PUT /api/v1/tasks/{id}`
- `DELETE /api/v1/tasks/{id}`
